\chapter{The Interactive Instrument}
\label{ch:instrument}

Beyond the batch pipeline, the same physics core drives an interactive
Vulkan application. This chapter documents it with one organising
principle stated up front: \emph{a hard wall separates physics from
presentation}. Everything that decides where a ray goes or how much
energy it carries lives in the validated core of
Parts~II--III; everything this chapter adds acts after that point, on
push constants and display look-up tables, and can be deleted without
changing a single measured number. The wall is enforced structurally
(the display layer has no write access to the geodesic or metric code
paths) and empirically (the \texttt{ctest} suite is byte-identical with
the display layer present or absent).

\section{Architecture and modes}
\label{sec:instrumentarch}

The engine is a single compute-to-present loop: a GLSL compute shader
(the fp32 sibling of the fp64 metrology shader of
Chapter~\ref{ch:gpu}) traces one geodesic per pixel into a storage
image, which is blitted to the swapchain; Dear ImGui draws the control
surface on top. All resources — render targets, LUTs, parameter
tables — live in one bindless descriptor array written at start-up.
The application boots to a menu whose backdrop is a $3840\times2160$,
$2\times2$-supersampled frame baked by the CPU reference tracer (33
million geodesics); the live renderer is deliberately idle behind the
menu.

Four modes expose the science: the live Kerr renderer with runtime
control of $(\astar, i, r_{\rm cam}, r_{\rm out}$, exposure, disk
temperature$)$; a Science Mode overlaying the fitted S2 orbit and its
data on the fit summary of Chapter~\ref{ch:fitting}, together with a
3-D orbit theatre that animates the five jointly fitted S-stars
(Chapter~\ref{ch:cluster}) along their \emph{integrated} GR geodesics
— the engine links the same Ceres-free orbit model the fitter uses and
replays its cached trajectories, with each star shaded by the exact
line-of-sight redshift $1+z$ of the trajectory sample (white when
approaching, through gold, to bronze when receding), the time axis
scalable from real \sgra{} wall clock to $10^{8}\times$; a no-hair panel
exposing $\epsq$ with the live analytic precession forecast of
Chapter~\ref{ch:nohair} beside the fitted confidence interval; and a
photon-ring scope that reframes the camera at $r = 60\,M$ with a narrow
field to isolate the $n=1$ ring visually. Camera orbit (mouse drag over
azimuth and inclination, scroll zoom $15$--$400\,M$) reprojects the
ZAMO tetrad of Chapter~\ref{ch:shadow} — moving the camera is a physics
operation and goes through the physics path.

\section{Presets and display grading}
\label{sec:presets}

Five named looks (FIRESTORM, GARGANTUA, ARCTIC, NEBULA, and CINEMATIC
SGR~A*) are $256\times1$
RGBA look-up tables generated by \texttt{scripts/gen\_luts.py},
applied to the physically shaded luminance. The CINEMATIC preset
additionally enables a volumetric display layer: a flared slab of
procedural dust banks, advected by the exact $\Omega(r)$ and shaded by
the same per-sample redshift factor and blackbody dictionary as the
midplane, is composited front-to-back along each geodesic — emissive
fog over unchanged physics, in the same spirit (and behind the same
wall) as the filament layer below. The physical option —
the Planck/CIE blackbody map of Chapter~\ref{ch:disk} — is the default
and is regenerated by the same script from the same colour code the CPU
renderer uses. Preset switches write a LUT index into push constants;
nothing else changes. Display dynamic range is handled by a calibrated
logarithmic window (24 stops mapped to the LUT domain), whose earlier
mis-calibration produced the ``brick disk'' bug hunt of
Chapter~\ref{ch:devhistory}.

\section{The display-only turbulence layer}
\label{sec:turbulence}

The reference physics disk is time-averaged and therefore perfectly
smooth; real accretion flows are filamentary. For the live instrument a
\emph{display-only} structure layer restores that texture — designed so
its every input is either the validated physics or pure presentation:

\begin{itemize}
\item \emph{Streamlines wound by the real shear.} The filament pattern
is value noise advected in azimuth by the exact circular-orbit rate
$\Omega(r)$ of eq.~\eqref{eq:omegacirc}: features at smaller radii
overtake those farther out precisely as Kerr orbital mechanics
dictates, winding the pattern into trailing spirals. The noise is
azimuthally periodic by construction (the seam lesson of
Chapter~\ref{ch:devhistory}).
\item \emph{Physical clock.} The advection speed is calibrated so that
a rotation-speed setting of $1.0$ equals real \sgra{} wall-clock time
($GM/c^3 = 21.2$~s per geometric time unit; one ISCO orbit
$\approx 8.5$ minutes), scalable to $1000\times$ for demonstration.
\item \emph{Translucent rim compositing.} Disk crossings composite
front-to-back with a transmittance term rather than terminating
opaquely, softening the rim; the modulation depth is $\pm2$ stops
around the Page--Thorne mean, leaving the radial photometry of
Chapter~\ref{ch:disk} intact on average.
\item \emph{Auto resolution.} A controller retunes the internal render
scale every two seconds toward a 13~fps target on the GTX 1050
(the $1/N_{\rm px}$ scaling of Fig.~\ref{fig:bench} makes the control
law exact); scales above $1\times$ provide supersampled stills.
\end{itemize}

None of these touches $(E, L_z, Q)$, the metric, or any measured
artefact; the spin-morphology observations of
Section~\ref{sec:spinmorphology} were made \emph{through} this layer,
which is why that section grounds each visual feature in the underlying
validated quantity ($r_{\rm ISCO}$, $g^4$, $\Omega(r)$) rather than in
the layer itself.

The same display layer carries a caustic de-aliasing stack for the
live fp32 path — a stiffness-adaptive polar step law, ray-property
triggered supersampling of axis-squeezed pixels, and band-limited
shading of the deepest pole-passing families — whose three-round
development, including the two regressions the first attempts caused,
is retold as a methods narrative in
Sections~\ref{sec:polarcolumn}--\ref{sec:crayon}. A black-background
toggle blanks the starfield backdrop entirely (display only; the
lensed disk image is unchanged) for silhouette study and clean
composites.

The same five fitted S-star orbits can also be drawn \emph{into the
live scene} rather than in a separate window. Each star's position
comes from the identical integrated geodesic, projected through the
exact inverse of the compute shader's camera model — the same ZAMO
triad, field of view and aspect convention — so the stars track the
mouse orbit and zoom for free and sit precisely where that camera
would see them; a star passing behind the silhouette is faded using
the Schwarzschild critical impact parameter $3\sqrt3\,M$ as the
occultation test. One honest caveat is displayed permanently in the
control panel: the fitted orbits are $\sim\!2\times10^{4}\,M$ across
while the modelled disk is $\sim\!20\,M$, so the \emph{radial scale}
is compressed by a labelled factor (typically $1\!:\!10^{3}$) to bring
both into one frame, exactly as published cluster renderings do.
Orbit shape, orientation, phase, period and the redshift colour are
the unmodified fit; only the overall size is a display choice, and
starlight bending is not applied to the star sprites, since at a
compressed radius it would not correspond to any real geometry.

\section{The control surface and the auto-resolution loop}
\label{sec:controls}

Interactivity is only useful if the frame rate survives it, and the
GTX-class test hardware saturates at roughly nine full-resolution
frames per second (one full geodesic per pixel;
Chapter~\ref{ch:gpu}). Rather than pick a fixed internal resolution,
the instrument closes the loop: every two seconds the frame-rate
sampler updates the internal render scale by
\begin{equation}
s \;\leftarrow\; \mathrm{clamp}\!\left(s\,
\sqrt{\tfrac{\mathrm{fps}}{13}},\; 0.25,\; 2.0\right),
\label{eq:autores}
\end{equation}
damped by blending most of the way toward the new value and ignoring
sub-5-per-cent changes to avoid render-target churn (each change
rebuilds the target and rewrites its bindless slot). The square root
is exact, not heuristic: the workload is one ray per pixel, so frame
time scales linearly with pixel \emph{count} and hence quadratically
with linear scale — the $1/N_{\rm px}$ law measured in
Fig.~\ref{fig:bench} makes \eqref{eq:autores} a one-step deadbeat
controller, the same design logic as the integrator's step
controller in Chapter~\ref{ch:numerics}. Scales above $1\times$
downsample through a linear blit, so the same slider doubles as a
supersampling control for stills. The rotation-rate slider is
calibrated so that $1.0$ advances the disk pattern at real \sgra{}
wall-clock rate ($GM/c^3 = 21.2$~s per unit of coordinate time; one
ISCO orbit every $8.5$ minutes) on a logarithmic range up to
$1000\times$ — at $1.0$ the disk is, correctly and instructively,
almost static to the eye, which is itself a physics statement about
how sedate a four-million-solar-mass hole's dynamics are in human
units.
